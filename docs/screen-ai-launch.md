# ScreenPilot — naming, positioning & video scripts

Marketing kit for the desktop AI screen-assistant (the two-button floating app
that captures the screen and asks Claude Haiku vision to explain a quiz answer
with a confidence score, or outline a coding approach).

Page for it: `screen-ai.html`.

---

## Positioning (important)

Present it as an **honest study / brainstorming / productivity tool** — a
real-time helper that understands your screen so you don't copy-paste into a
chat and switch tabs. It checks your own thinking, unblocks you, and shows a
confidence score so the output is transparent.

Do **not** market it as "solve tests / pass interviews / beat LeetCode for you."
That framing reads as cheating, hurts trust, and sits badly next to your
business brand. Always add a "use responsibly, within the rules of your
exam/course" line (already on the page).

---

## Name ideas

**App name (recommended): ScreenPilot** — implies a light co-pilot over your
screen. Other options:
- OverlayAI — emphasises the floating overlay.
- ContextAI / SnapSolve — emphasises one-click screen understanding.
- AI Vision Desktop — emphasises Claude's multimodal vision.
- Smart Screen Companion — the friendliest, most "study helper" framing.

## Short-form script (Reels / Shorts / TikTok) — ~35–45s

> Positioning tweak vs. the draft you had: emphasise "understand & check
> yourself," not "solve it for you."

**0:00–0:05 · Hook**
- Visual: a hard quiz / coding task open; a tiny 2-button app floats in the corner; cursor clicks button 1.
- On-screen text: "I built an AI that reads my screen…"
- VO: "No more copy-pasting questions into a chat. I built a little app that reads my screen and helps me in one click."

**0:05–0:15 · Demo 1 — quizzes**
- Visual: click button 1 → capture flash → a panel appears: "Option B — 96%".
- VO: "Button one is for study. It snapshots the screen, sends it to Claude Haiku vision, and gives the likely answer with a confidence score — so I can check my own reasoning."

**0:15–0:28 · Demo 2 — coding**
- Visual: a LeetCode-style task → click button 2 → a formatted approach + sample + O(n) note.
- VO: "Button two is for code. It reads the task from the image and returns a worked approach and a solution with its complexity — no alt-tabbing."

**0:28–0:38 · Tech**
- Visual: a glimpse of the Python code / clean GUI.
- On-screen text: "Claude Haiku + Computer Vision"
- VO: "It runs on Claude Haiku, so answers come back almost instantly and cost very little."

**0:38–0:45 · CTA**
- Visual: you on camera / blurred screen bg.
- On-screen text: "Open-source it on GitHub? 👇"
- VO: "Would you use something like this? Tell me in the comments if I should put the code on GitHub."

**Editing notes**
- Big captions (70% watch muted); cut all pauses; light Tech / Lo-Fi / Synthwave track.
- Safety: make sure no API keys or personal data are visible in any frame.

---

## Long-form outline (YouTube, 5–8 min)
1. Hook — show the click-to-answer in the first 5 seconds.
2. Problem — copying text/images into a chat and tab-switching is slow.
3. Tech — Python overlay, screen capture (mss/Pillow), Claude Haiku vision (why Haiku: fast + cheap + multimodal).
4. Use cases — quiz (confidence + explanation), coding task (approach + sample + complexity).
5. Transparency — highlight the confidence score as an honesty feature.
6. CTA — ask whether to open-source it / share the utility.

---

## Notes / honesty
- No invented usage numbers or "costs pennies" hard claims — keep it qualitative
  ("fast and low-cost") unless you have real figures.
- Keep the responsible-use line in the video description too, not just on the page.
